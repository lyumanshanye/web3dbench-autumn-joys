Build a standalone Three.js browser app called “Patrol Route Studio.” Use only local starter dependencies and procedural geometry; make no runtime network requests. Use meters, Y-up coordinates, character-forward local +Z, fixed steps dt=1/60 second, and numeric tolerance 1e-5. Expose `window.patrolStudio` with `scene`, `camera`, `renderer`, `controls`, `character`, `routeLine`, `leftLeg`, `rightLeg`, `getState()`, `setPlaying(flag)`, `setMode(mode)`, `step(n)`, `setWaypoint(i,x,z)`, `save()`, `load()`, `importState(text)`, and `reset()`.

1. Create a responsive scene with ambient and directional lighting, OrbitControls, and a PerspectiveCamera(50,aspect,0.1,100) initially at (8,7,10), looking at (0,0,0). Add a 16×12 ground plane at y=0. Build `character` as a Group containing a 0.6×0.8×0.35 body centered at local y=1.1 and two 0.18×0.7×0.18 legs pivoted at local (±0.18,0.7,0), with geometry extending downward. The default route is A=(-3,0), B=(3,0), C=(3,4), displayed by a continuously updated line at y=0.03 and three waypoint markers.

2. Initial state is position A, yaw 0, targetIndex 1, steps 0, distance 0, mode `walk`, playing false, and locomotion state `idle`. Modes are `walk` at 2 m/s and `run` at 4 m/s. While playing, each `step(1)` moves toward the current target by min(modeSpeed/60,remainingDistance), sets yaw to atan2(dx,dz) for a nonzero horizontal target delta, and adds actual travel to distance. On exact arrival, increment targetIndex modulo route length; discard unused movement and advance at most one waypoint per step. `step(n)` performs exactly n fixed steps regardless of rendering, and pausing must not change position, targetIndex, steps, or distance.

3. While playing, locomotion state equals mode; otherwise it is `idle`. Define phase=2π*distance/1.2. While playing set leftLeg.rotation.x=0.6*sin(phase) and rightLeg.rotation.x=-0.6*sin(phase); while paused set both to zero. Update the character's world transform and route display after every API operation.

4. `setWaypoint` accepts integer indices 0–2 and finite coordinates within x=[-8,8], z=[-6,6]. It returns true and preserves playback state on success. Out-of-range indices, nonfinite coordinates, boundary violations, or routes that would make any consecutive segment (including C-to-A) shorter than 0.5 return false without mutation and set `lastError` to a nonempty string.

5. `getState()` returns a JSON-safe object containing version 1, route, mode, playing, steps, position, yaw, targetIndex, distance, locomotion, and lastError. `save()` stores that object in localStorage key `patrol-route-studio-v1` and returns its JSON text. `load()` and `importState(text)` validate the same fields, types, route constraints, targetIndex range 0–2, nonnegative integer steps, and nonnegative finite distance; valid input restores the complete simulation and returns true. Missing saves, malformed JSON, or invalid values return false without changing the current scene or state.

6. Provide Play/Pause, Walk/Run, Save, Load, and Reset controls wired to the API. `reset()` restores every initial value and the default route but does not delete the saved slot. Clear `lastError` after every successful API operation.
