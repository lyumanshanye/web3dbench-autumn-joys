Extend the existing FPS with deterministic, collision-aware enemy spawn placement. Preserve the current scene, weapons, controls, health, kill/respawn flow, and building geometry except for the spawn behavior below. Use local code and procedural geometry only; add no remote assets or runtime network requests.

1. Add a reusable planner and expose `window.spawnLab` with `plan(request)`, `loadFixture()`, `getState()`, and `reset()`. A request has exactly the relevant fields `{count,minDistance,maxDistance,player:[x,z],obstacles:[{id,min:[x,z],max:[x,z]}],occupied:[[x,z]]}`. `plan` must not mutate the scene and returns `{positions,missing}`, where each position is `[x,0.5,z]` and `missing` is the number of requested enemies for which no position was found. Require finite numeric coordinates, integer `count` from 0 through 16, integer distances satisfying `0 <= minDistance <= maxDistance <= 100`, and ordered obstacle bounds. Throw `RangeError` for invalid input without changing lab state.

2. Use an enemy footprint radius of 0.75 and Y-up world coordinates. For each requested enemy, search radii from `maxDistance` down to `minDistance` inclusive in steps of 1. At each radius `r`, test 32 angles in order `j=0…31`, with `a=2πj/32`, `x=player[0]+r*sin(a)`, and `z=player[1]+r*cos(a)`. Restart this complete ordering for every enemy and select the first valid candidate.

3. Reject a candidate when `abs(x)>49.25` or `abs(z)>49.25`. Reject it when it touches or enters an expanded obstacle: `x>=minX-0.75 && x<=maxX+0.75 && z>=minZ-0.75 && z<=maxZ+0.75`. Also reject it when its XZ distance to any occupied point or previously planned position is strictly less than 1.5; exactly 1.5 is allowed. If no candidate survives, increment `missing` and continue with the next requested enemy.

4. `loadFixture()` must suspend normal enemy AI and spawning, then call `plan` with `{count:2,minDistance:10,maxDistance:10,player:[0,0],obstacles:[{id:"block",min:[-1,9],max:[1,11]}],occupied:[]}`. Create a procedural ground plane, a box named `fixture-block` representing those XZ bounds with height 2 and center y=1, and two existing `Enemy` groups named `spawn-fixture-0` and `spawn-fixture-1` at the returned positions. The expected positions are `[1.9509032202,0.5,9.8078528040]` and `[3.8268343237,0.5,9.2387953251]`.

5. `getState()` returns the last request, result, fixture enemy world positions, and whether fixture mode is active. `reset()` removes only fixture enemies, fixture geometry, and lab state, then restores ordinary game updating; it must not reset weapons, health, kills, buildings, or the player camera.

6. Integrate the planner into ordinary `spawnEnemies`: use the camera XZ as player, distances 20 and 40, living enemy XZ positions as occupied points, and world-space XZ bounds of non-destroyed, non-passable meshes in `window.walls` as obstacles. Create only planned positions, preserve initial and on-death spawn counts, and skip positions when the planner reports them missing rather than reverting to random placement.
