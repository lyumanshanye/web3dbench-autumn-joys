Build a standalone Three.js browser page called “Polar Harbor Lab.” Use only locally available Three.js code, procedural geometry, and solid-color materials; load no models, textures, fonts, data files, or remote assets and make no runtime network requests. Use XY as the play plane, +Z toward the camera, radians, and world units. Numeric comparisons use tolerance 1e-5.

1. Create a full-window canvas, a PerspectiveCamera(75, aspect, 1, 200) at (0,0,100) looking at the origin, ambient and directional lighting, and a 500×500 water plane at z=-4. Add an island cylinder of radius 8 and height 4 centered at (0,0,-2), a 64-segment circular track of radius 50 in z=0, and a procedural ship group named `ship` made from boxes/cones. The ship remains at radius 50 and z=0. Its position is `(50*cos(angle),50*sin(angle),0)` and its rotation.z is `angle` when direction is +1 or `angle-Math.PI` when direction is -1. Initial angle is Math.PI/2 and direction is +1.

2. Create 31 gold coins in a group named `coins`, using CylinderGeometry(2,2,0.5,16) rotated x=Math.PI/2. For fixture index i=0…30, set angle=`Math.PI/2+(i+1)*2*Math.PI/32`, position=`(50*cos(angle),50*sin(angle),0)`, and name=`coin-${i}`. Collected coins remain children but become invisible. Use dark SphereGeometry(2,16,16) cannonballs in a group named `cannonballs`.

3. Expose `window.harborLab` with `scene`, `camera`, `ship`, `coins`, `cannonballs`, `step(ms)`, `toggleDirection()`, `spawnBall(angle,radius)`, `reset()`, and `getState()`. Do not advance simulation from requestAnimationFrame; rendering may continue, but motion occurs only through `step`. `step(ms)` accepts only integers from 0 through 10000; otherwise throw RangeError without changing state. Advance in exact 1 ms ticks: increase time, move angle by `direction*0.0014`, increase every existing ball radius by 0.035, then spawn a ball at radius 0 whenever time is divisible by 750. Automatic spawn angles cycle through 0, Math.PI, Math.PI/2, 3*Math.PI/2. Ball position is `(radius*cos(angle),radius*sin(angle),0)`.

4. After each tick, collect every visible coin whose ship-to-coin Euclidean distance is <=6, adding one score point per coin. A ball destroys the ship when its distance to the ship is <=6. Set status to `destroyed` on a hit, or `won` when all coins are collected; once either terminal status is reached, later ticks and steps change nothing. `spawnBall` accepts finite angles and radii from 0 through 50 and returns the created mesh; reject other inputs with RangeError.

5. `toggleDirection()` multiplies direction by -1 and immediately updates ship rotation. `reset()` restores time=0, score=0, angle=Math.PI/2, direction=+1, status=`running`, all coins visible, no balls, and the initial ship transform. `getState()` returns a fresh plain object containing time, score, angle, direction, status, collectedCount, and ballCount. Add buttons for Step 1 ms, Step 100 ms, Toggle, and Reset plus a text readout mirroring `getState()`; API calls and buttons must produce identical updates.
