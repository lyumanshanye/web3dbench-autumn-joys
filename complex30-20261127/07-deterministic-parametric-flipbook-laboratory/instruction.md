Build a standalone Three.js browser app called “Flipbook Lab.” Use only local Three.js and procedural geometry/materials; make no runtime network requests and load no textures, models, fonts, or animation libraries. Use Y-up world units, radians, and numeric tolerance 1e-5. Expose window.flipbookLab with scene, camera, renderer, book, sheets, setProgress(p), getProgress(), getGoal(), flipTo(target), nextSheet(), previousSheet(), advance(dt), reset(), flipSheet(i), and pick(ndcX,ndcY).

1. Create a full-window scene with resize handling, a perspective camera (FOV 45, near 0.1, far 100) at (0,2.6,2.8) looking at the origin, ambient light, and directional light. Set book = new THREE.Group() and add four sheet groups named sheet-0 through sheet-3 in index order. Each sheet must contain a DoubleSide mesh made from PlaneGeometry(1.2,0.8,24,16), rotated X by -PI/2 and then translated X by 0.6, so its undeformed bounds are x=[0,1.2], y=0, z=[-0.4,0.4]. Give sheets distinct solid colors and store each zero-based index in sheet.userData.sheetIndex.

2. Define N=4 and spacing=0.01. setProgress(p) must immediately clamp finite p to [0,4], cancel any goal, and rebuild all sheet states. For sheet i, its flip q is 0 when i>floor(progress), 1 when i<floor(progress), and the fractional part f when i=floor(progress); at integer progress 4 every q=1. Set sheet.rotation.z=PI*q. Let rightY=-spacing*i, leftY=-spacing*(N-i), and yBlend=max(0,2*q-1); set sheet.position.y=rightY+yBlend*(leftY-rightY). Set book.position.x to -0.3+0.3*f when floor(progress)=0, 0.3*f when floor(progress)=N-1, 0.3 when progress=N, and 0 otherwise.

3. Deform every sheet mesh from its original undeformed coordinates on each rebuild: for original local x in [0,1.2], set local position.y=0.08*sin(PI*q)*sin(PI*x/1.2), retain x and z, and recompute vertex normals. Thus at progress 1.5 the center vertex of sheet-1 has local y=0.08, while completed and untouched sheets are flat. Do not accumulate deformation between calls.

4. flipTo(target) clamps a finite target to [0,4], stores it as the goal, and leaves progress unchanged until advance(dt) is called. advance(dt) ignores negative or non-finite dt and otherwise moves progress toward the goal at 2 sheet units per second without overshoot, rebuilding geometry and transforms after every movement. nextSheet() targets min(4,floor(progress+1e-9)+1); previousSheet() targets max(0,ceil(progress-1e-9)-1). reset() sets progress and goal to 0 and rebuilds immediately.

5. flipSheet(i) must do nothing for an invalid index; otherwise call flipTo(i) when progress>i, or flipTo(i+1) otherwise. pick(ndcX,ndcY) raycasts recursively against book using the supplied normalized device coordinates, identifies the first hit’s sheet ancestor, calls flipSheet for it, and returns its index; return null for no hit. Canvas pointer clicks must convert coordinates to NDC and use this same picking path.

6. Provide a progress slider (min 0, max 4, step 0.001), Next, Previous, and Reset buttons, and readouts for progress and goal. Slider input calls setProgress; buttons call the corresponding API. Keep controls synchronized after every API operation. Non-finite setProgress or flipTo inputs must be ignored without changing progress, goal, geometry, or transforms.
