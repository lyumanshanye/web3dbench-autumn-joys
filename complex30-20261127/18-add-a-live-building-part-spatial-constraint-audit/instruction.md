Extend the existing OSMBuilding viewer with a deterministic spatial-constraint audit while preserving its current building geometry, OrbitControls, file loading, and info GUI.

1. Audit mode is enabled only when the URL contains the `audit` query parameter. The evaluation URL is `?type=way&id=100&fromFile=./test/data/spatial-audit.osm&audit`. Loading that URL must use the supplied local XML and make no OSM API request. Without `audit`, do not create audit helpers or change existing behavior.

2. After the initial building meshes have been added, expose `window.osmAudit` with `refresh()` and `getReport()`. `refresh()` must call `scene.updateMatrixWorld(true)`, discard the previous report and helpers, recompute from live meshes, and return the new report. `getReport()` returns the latest report. The report is `{outerId:"100", parts:[...], issues:[]}`, with parts sorted by numeric OSM id. Each part entry is `{id, bounds:{min:[x,y,z],max:[x,y,z]}, footprint:[minX,minZ,maxX,maxZ], baseY, topY, contained, heightViolation}`.

3. For each part, find its wall mesh named `b<id>` and compute bounds with `new THREE.Box3().setFromObject(wall)` in world coordinates. Compute the outer reference identically from `b100`, including it even though it is invisible. Keep this internally computed outer-wall Box3 as `outer.bounds` for the formulas below; `outer.bounds` is not a serialized report field. `baseY` and `topY` are the part bounds minimum and maximum Y. With epsilon `0.001` in every comparison, `contained` is true exactly when all four part footprint limits lie within the outer footprint, allowing epsilon at each boundary. `heightViolation` is `topY > outer.bounds.max[1] + 0.001`. Do not use roof meshes, helper objects, visibility, or raw latitude/longitude for these calculations.

4. Add a scene group named `spatialAudit`. On every refresh, remove and dispose its previous children, then add one `Box3Helper` for the outer wall and one per valid part. Use blue `0x0000ff` for the outer box, green `0x00ff00` for a part that is contained and has no height violation, and red `0xff0000` otherwise. Each part helper must use the same Box3 instance used to populate its report entry's bounds arrays, and the outer helper must use the internally computed outer-wall Box3. Helpers must not alter building meshes, materials, camera, or controls.

5. The supplied fixture has outer way 100 and parts 201 and 202. Part 201 is inside the outer footprint and below its top; part 202 crosses the outer footprint and is taller than the outer wall. Therefore the initial report must classify 201 as contained with no height violation and 202 as neither contained nor height-compliant. Recomputing after a mesh transform or geometry replacement must use the new live bounds, not cached XML dimensions.

6. If an expected outer or part wall is missing or produces an empty Box3, append a human-readable string containing its id to `issues`, omit an invalid part entry and its helper, and continue auditing other parts. If the outer reference is invalid, set every valid part's `contained` and `heightViolation` to false. Refresh resets only audit state; it must not reload XML, rebuild the building, or reset user camera/control state.
