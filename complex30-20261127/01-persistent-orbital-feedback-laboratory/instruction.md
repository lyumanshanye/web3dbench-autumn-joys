Build a standalone Three.js browser app called “Orbital Feedback Laboratory.” Use only local starter dependencies and procedural geometry/materials; make no runtime network requests and load no models, textures, fonts, or shader files. Use Y-up world units and numeric tolerance 1e-5. Expose `window.orbitFeedback` with `scene`, `camera`, `renderer`, `controls`, `probes`, `getState()`, `step(count)`, `setPaused(value)`, `setSpeed(id,value)`, `setRadius(id,value)`, `selectAt(clientX,clientY)`, `save()`, `load()`, and `reset()`.

1. Render an 800×600 canvas with a PerspectiveCamera at `(0,8,12)`, looking at the origin, plus OrbitControls. Add a central cylinder of radius 0.6 and height 1 centered at the origin. Create three sphere probes with radius 0.22 and IDs `p0`, `p1`, `p2`. Their respective initial `(angle,radius,height,speed)` values are `(0,2,0.5,1)`, `(2π/3,2.8,1,-1.5)`, and `(4π/3,3.6,1.5,2)`. Angles are radians and speeds are radians per second. Give each probe a distinct solid color and a Line trail.

2. Maintain `time`, integer `frame`, and `paused`, initially `0`, `0`, and `false`. `step(count)` must synchronously advance exactly `count` fixed frames even while paused, using `dt=1/60`; reject non-integer or negative counts by returning `false` without mutation, otherwise return `true`. For each frame and probe, update `angle += speed*dt`, then set world position to `(radius*cos(angle),height,radius*sin(angle))`. Increment `time` by `dt` and `frame` by one. Append each resulting position to that probe’s trail, retaining at most 120 points including the current point. Continuous rendering may advance time only while unpaused and must use the same fixed-step rule.

3. `setPaused(value)` stores a strict boolean. `setSpeed` accepts finite values in `[-4,4]`; `setRadius` accepts finite values in `[1.5,4]`. Both return `true` on success. Unknown IDs, non-finite values, or out-of-range values return `false` and leave all state unchanged. Radius changes affect the next computed position; they do not rewrite existing trail points.

4. Implement `selectAt` with a Raycaster and canvas-relative pointer coordinates derived from the canvas bounding rectangle. A hit on a probe sets `selectedId` to its ID and gives only that probe emissive intensity 0.8; a miss sets `selectedId=null` and all emissive intensities to 0. Return the selected ID or `null`.

5. `getState()` returns a deep-copy JSON-safe snapshot containing `version:1`, time, frame, paused, selectedId, every probe’s angle/radius/height/speed/current position, and all retained trail points. `save()` writes that snapshot to localStorage key `orbitFeedback.v1` and returns the snapshot. `load()` restores a valid saved snapshot, including trails, pause, and selection, returning `true`; malformed JSON, wrong version, missing fields, or invalid numeric values return `false` without changing live state. Automatically attempt `load()` at startup.

6. Provide Pause, Save, Load, and Reset buttons and a text readout of frame, time, paused, and selectedId. `reset()` removes the storage key and restores every initial value, including empty selection, cleared trails, default camera and controls, and unpaused state; it must not merely reload the page.
