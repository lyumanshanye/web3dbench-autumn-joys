Build a standalone Three.js browser page called “Keyframe Clip Foundry.” Use only local starter Three.js code, procedural geometry, solid-color materials, inline JavaScript, and ordinary DOM. Load no models, textures, fonts, animation libraries, or remote data, and make no runtime network requests. Render continuously, but advance animation only through the API below.

1. Use meters, Y-up coordinates, and seconds. Create a rig named `rig` at world origin with a torso mesh named `torso` using BoxGeometry(1, 1.4, 0.6) at local (0, 1.4, 0). Add a Group named `shoulder` at local (0.75, 1.9, 0), containing an `upperArm` BoxGeometry(0.3, 1, 0.3) mesh at local (0, -0.5, 0). Add a ground grid and a perspective camera at (4, 3, 6) looking at (0, 1.2, 0). Provide DOM readouts for clip, time, playing state, fade progress, and event count.

2. Store these inline clips as plain JavaScript data. `idle`: duration 2, loop true, root Y track times [0,1,2] values [0,0.1,0], arm Z track values [0,0,0]. `walk`: duration 1, loop true, root Y times [0,0.5,1] values [0,0.08,0], arm Z values [0,0.6,0]. `wave`: duration 1.5, loop false, root Y times [0,0.75,1.5] values [0,0,0], arm Z values [0,2.4,2.4]. Root Y means `rig.position.y`; arm Z means `shoulder.rotation.z` in radians. Sample each track with linear interpolation between surrounding keys and endpoint clamping. Looping clips use time modulo duration, so sampling exactly at duration gives the first key; non-looping clips clamp at their final key.

3. Expose `window.clipLab` with `seek(t)`, `step(frames)`, `play()`, `pause()`, `setClip(name, fadeSeconds)`, `reset()`, and `getState()`. Start paused on `idle` at time 0. `seek(t)` sets the current clip time and samples immediately. `step(frames)` advances exactly `frames/60` seconds even while paused; `play()` enables automatic fixed 1/60-second advancement per rendered frame and `pause()` disables it. A finished non-looping clip automatically pauses at its duration. Reject non-finite or negative times, frame counts, and fade durations with `RangeError` without changing state.

4. `setClip(name, fadeSeconds)` switches to the named clip at target time 0. With fade 0, apply the target immediately. Otherwise freeze the complete outgoing sampled pose at transition start and blend it to the advancing target pose using `u=clamp(fadeElapsed/fadeSeconds,0,1)` and weight `s=u*u*(3-2*u)`; interpolate root Y and arm Z as `outgoing*(1-s)+target*s`. The target clock and fade clock both advance only through normal time advancement. An unknown clip name throws `RangeError` without changing state.

5. Emit `wave-start` when `wave` is entered and `wave-peak` when its local time first reaches or passes 0.75. Keep an ordered event log and expose it in `getState()`, along with clip, time, playing, finished, fadeElapsed, fadeSeconds, rootY, and armZ. `reset()` restores the initial paused idle pose, clears the log, and cancels any fade. Invalid input must not append events.
