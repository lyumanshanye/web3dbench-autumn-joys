Build a standalone Three.js browser page called “Exclusion Shard Field Lab.” Use only the clean starter’s local Three.js and OrbitControls, procedural geometry, solid-color materials, inline CSS/JavaScript, and ordinary DOM. Load no models, textures, fonts, animation libraries, or remote assets and make no runtime network requests. Use Y-up world units, XYZ Euler order, radians, and numeric tolerance 1e-5.

1. Create a full-window scene with PerspectiveCamera(60, aspect, 0.1, 100) at (0,0,8), looking at the origin, and non-auto-rotating OrbitControls. Add ambient and directional lighting. Create `core`, an IcosahedronGeometry(1,1) mesh at the origin, and `group`, containing exactly 125 BoxGeometry(0.1,0.1,0.1) meshes. Iterate x, then y, then z, each from -2 through 2; name each cube `cube_x_y_z`, position it at (x,y,z), and set its rotation to (0.1*x,0.1*y,0.1*z).

2. Expose `window.shardFieldLab` with `scene`, `camera`, `renderer`, `controls`, `core`, `group`, `scatter(seed)`, `step(dt)`, `reset()`, and `getState()`. `getState()` returns `{seed, elapsed, scattering}` plus arrays of each cube’s current position, start position, and target position in group-child order. Also store the current transition’s start and target as `cube.userData.scatterStart` and `cube.userData.scatterTarget`.

3. `scatter(seed)` must generate a complete replacement layout without using Math.random. Set the PRNG state to `seed >>> 0`; for every draw update it with `state = (1664525 * state + 1013904223) >>> 0` and return `state / 4294967296`. Process cubes in group-child order. Each attempt consumes three draws and proposes `(5*(u1-0.5), 5*(u2-0.5), 5*(u3-0.5))`. Accept only if its distance from the origin is at least 2 and its distance from every already accepted target is at least 0.35. Allow 4000 attempts per cube; on exhaustion, throw an Error and leave the entire existing layout and transition state unchanged.

4. A successful scatter records all starts and targets before moving anything, sets `elapsed=0` and `scattering=true`, and animates for one second per cube. Cube i has delay `0.05*(i%5)`. During `step(dt)`, local time is `clamp(elapsed-delay,0,1)`, interpolation weight is `q=t*t*(3-2*t)`, and position is `start+(target-start)*q`. At local time 1, assign the target exactly. Set `scattering=false` only when elapsed is at least 1.2. Ignore negative, NaN, or infinite dt; otherwise add dt to elapsed. Also set core rotation to `(0.2*elapsed,0.3*elapsed,0)` on every accepted step. Do not advance simulation from wall-clock time.

5. `reset()` restores the exact initial lattice positions and rotations, core rotation (0,0,0), seed 0, elapsed 0, and scattering false; clear each cube’s scatter start and target to null. It must not recreate geometry, reset the camera, or alter controls. Provide Scatter and Reset buttons; Scatter reads an integer seed from a numeric input whose default is 12345.

6. Render continuously and handle resize by updating camera aspect, projection matrix, and renderer size. All motion and layout changes must come only from the specified API or buttons, so repeated seeds and step sequences produce identical states.
